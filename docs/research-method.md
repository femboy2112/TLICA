## The six-line seed

The whole page unpacks one thing the author said about her own recurring method:

> Find analogy that fits phenomena phenomenologically.
> Map the analogy to math.
> Now you have a model.
> Drive the math with inputs not yet phenomenologically experienced and see what drops out.
> Test those against reality.
> Update the model based on results.

That is an **author self-report** (status: *Observed*). It is preserved verbatim as the seed of
the dossier. Everything below is a *reconstruction* of it — and a reconstruction is a second
object, not the same thing as the report it reconstructs.

## The one rule that keeps it honest

Three clauses, in order, and the order is the whole point:

> **Analogy proposes candidate structure. Mathematics propagates consequences. Reality supplies warrant.**

An analogy is where a model comes *from*, never why you should *believe* it. Math can make a
consequence certain *inside* the model without making the model true *about the world*. Only a
test against something you didn't already use to build the model pays for belief. Skip the third
clause and you have a metaphor wearing a lab coat.

## The loop

A phenomenon whose shape you can describe *without* already naming its cause →

```
  phenomenon
     │  (search for a source analogy that exposes a candidate structure)
     ▼
  analogy
     │  (declare a BRIDGE CONTRACT — what maps, and what explicitly does not)
     ▼
  candidate shared structure     ← strip the source imagery; keep the structure
     │  (formalize into a model with an OBSERVATION MAP back to measurable things)
     ▼
  formal model
     │  (drive it into a regime you did NOT use to build it)
     ▼
  risky prediction
     │  (predeclare a discriminating probe: pass / fail / ambiguous, with controls)
     ▼
  compare prediction ⇄ reality
     │  (localize the residual: which stage broke?)
     ▼
  revision  ──────────────────────────┐
     └──────────────────────────────── back to the model (or, honestly, to REFUTED)
```

The epistemic *direction* flips halfway through. Building the model (phenomenon → analogy →
structure → model) is **abductive** — creative, cheap, unwarranted. Deriving a prediction from
the model is **deductive** — certain *within the model's assumptions*. Comparing to reality is
**empirical** — the only step that adds warrant. Keeping those three separated is what stops
"the math is airtight" from being mistaken for "the theory is true."

## The bridge contract

No declared bridge, no transported claim. Before any structure crosses from the source analogy
to the target, you write down five things:

| Component | What it declares |
|---|---|
| **objects** | which source objects stand in for which target objects |
| **relations** | which source relations are claimed to hold in the target |
| **invariants** | what is proposed to be preserved |
| **dynamics** | which source rules of change are claimed to carry over |
| **non-transports** | what about the source is **explicitly NOT** imported |

That last row is the one people skip and the one that does the work: naming what does *not*
carry over is how you stop the source domain's irrelevant baggage from sneaking into the target
as if it had been earned.

## Fit is not holdout

Everything that *materially shaped* the analogy, the bridge, the model family, the parameters, or
the interpretation is **fit provenance**. It cannot then turn around and serve as clean
validation of the same construction — you cannot test a model on the very evidence you tuned it
to. This is just honest bookkeeping, but it is the bookkeeping that autobiographical and
introspective modeling most often gets wrong: your "novel" example may already be contaminated by
implicit familiarity with your own history.

## The generative hinge: drive the math out of fit

The move that separates a real model from an elaborate redescription is choosing an input **`u*`
outside the motivating evidence**, pushing it through the model's observation map, and seeing what
drops out — *before* you look at reality. A model that only ever reproduces the cases used to
build it has excluded nothing and predicted nothing. A model earns its keep exactly when it can
**surprise its own author** in a regime nobody fit it to.

## The probe, and letting it fail

A probe is worth running only if you predeclare what each outcome means:

- **pass** — the risky prediction is borne out under the stated conditions;
- **fail** — it is not, and that counts;
- **ambiguous** — the probe could not discriminate, stated up front rather than after the fact;
- **controls** and, where possible, **rival predictions** a live competitor would make.

And the loop must permit **REFUTED as a stable terminal outcome.** If every bad result can be
absorbed by some unconstrained patch while the central claim stays untouchable, the program is
self-sealing and has quietly stopped exposing itself to reality. Refuted has to be a place the
method can actually end up — the repository has real examples where it did (see below).

## When a prediction misses: localize the residual

A failed prediction is not one undifferentiated failure. It can be provisionally assigned to a
specific stage — which turns "it didn't work" into a next experiment instead of a shrug:

| Failure locus | The thing that was actually wrong |
|---|---|
| analogy selection | the source domain was a poor match to begin with |
| bridge transport | something was carried over that shouldn't have been (or vice-versa) |
| formalization | the structure was encoded incorrectly |
| parameters | the structure is right; the numbers are off |
| observation map | the model is fine; the link to a measurable quantity is wrong |
| probe | the test itself couldn't discriminate |
| domain boundary | the model is valid, but not in the regime probed |
| source / provenance | a fit-vs-holdout or contamination problem upstream |

(A real failure can implicate more than one at once; the decomposition narrows the search, it
does not guarantee a unique culprit.)

## The four warrant boundaries

1. **Phenomenology → analogy.** A good fit licenses *"this source may expose useful structure,"*
   never *"the target literally is the source mechanism."*
2. **Analogy → mathematics.** A clean formalization licenses *"these consequences follow from
   this transported structure,"* never *"the structure is empirically correct."*
3. **Prediction → observation.** A successful prediction is evidence for the *tested* claim under
   the *tested* conditions — it does not validate every part of the model, since several model
   variants may entail the same prediction.
4. **Repeated success → generality.** Surviving many independent regimes corroborates a model;
   it does not establish final truth outside what was tested. The honest endpoint is *dominance
   within a stated boundary*, not metaphysical finality.

**But these are all the same author's project.** Common provenance is not independence: they show

corroborate that the method is generally good. That claim (C-019) is still **UNVERIFIED**, and the
lamp it needs is a prospective, comparative study — not more examples from the same source.

> **In plain terms —** this is the project being honest about its own workshop. A resonance or a
> pretty analogy is where an idea is *born*, and that's allowed to be unrigorous. What's *not*
> allowed is treating the birth certificate as proof the idea is right. So the method makes you
> write down exactly what you borrowed, formalize it, push it somewhere new, and then go let
> reality have a clean shot at it — including the shot where reality wins and the idea is marked
> wrong. That last part is the feature, not the bug.
